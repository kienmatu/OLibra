# Laravel Migration — Phase 0: Foundation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Draft

**Goal:** A running Laravel + Inertia + React application on MariaDB 10.11 carrying the complete OLibra schema — all ten generated-column uniques, all fifteen composite tenant FKs, the triggers, the DbGuarantees and TenantIsolation suites — plus models, enums, tenancy, authentication, the app shell, CI and the deploy pipeline, with no business feature yet.

**Architecture:** Laravel 13 at the repository root on the long-lived `laravel` branch, Inertia v2 bridging to React 19; the Next.js tree stays untouched as the reference implementation. Tenancy is three layers: composite FKs in the schema, a `BelongsToBookshelf` global scope reading a request-scoped `TenantContext`, and Gates over the membership role hierarchy. Pure functions (folding first among them) live in `app/Support`, tested without booting the framework.

**Tech Stack:** PHP 8.4, Laravel 13, Inertia v2, React 19, Tailwind v4, MariaDB 10.11, Pest 5, Larastan level 8, Pint, Biome 2, Vite 6, Ziggy 2, Bun (local JS toolchain), Docker + FrankenPHP (local dev only — production is cPanel/Apache/PHP-FPM).

**Spec:** docs/superpowers/specs/2026-08-26-laravel-mariadb-inertia-migration-design.md

**Scope note:** Phase 0 is one plan, deliberately. Its 21 tasks are a single dependency chain (survey → scaffold → fold → schema → guarantees → models → tenancy → auth → shell → CI → deploy) with no seam where half a foundation would be a usable deliverable; splitting it would only manufacture a second plan whose first task is "finish the first plan". It is, however, the largest plan this repository will carry, and tasks must be committed one at a time as the header requires.

## Global Constraints

- **Branch:** all work on the long-lived `laravel` branch off `main`. The Next.js tree (`src/`, `next.config.ts`, `compose.yaml`, `tests/`, …) is never modified, moved or deleted in this phase.
- **Database:** MariaDB **10.11** (the real host runs 10.11.13-cll-lve-log). Local dev and CI pin the `mariadb:10.11` image. Laravel's `mariadb` driver, not `mysql`.
- **PHP:** **8.4** (Laravel 13 requires ≥ 8.4.1). `composer.json` requires `"php": "^8.4"`. If the host survey (Task 1) finds no PHP 8.4, the fallback is `laravel/framework:^12` on PHP 8.3 — a decision recorded in `docs/HOSTING.md` before Task 2 runs, not improvised.
- **Versions:** Laravel `^13.0`, `inertiajs/inertia-laravel` `^2.0`, `@inertiajs/react` `^2.0`, React `^19`, Tailwind CSS `^4.0` via `@tailwindcss/vite`, `tightenco/ziggy` `^2.4`, Pest `^5.0`, `larastan/larastan` `^3.0` at **level 8**, `@biomejs/biome` `^2.5`.
- **No Redis, no daemons:** `CACHE_STORE=database`, `SESSION_DRIVER=database`, `QUEUE_CONNECTION=database`. Queue work is drained by the per-minute scheduler tick running `queue:work --stop-when-empty --max-time=50`. Nothing may depend on a long-running worker.
- **Primary keys:** UUIDv7 in `CHAR(36) CHARACTER SET ascii COLLATE ascii_bin`, generated by Eloquent's `HasUuids` (which produces `Str::uuid7()` in Laravel 13 — the spec's "HasVersion7Uuids" is this trait's current name for v7 behaviour). One exception: `audit_log.id` is `BIGINT` auto-increment, as today.
- **Timestamps:** `DATETIME(6)` storing **UTC** (`APP_TIMEZONE=UTC`); rendering in `Asia/Ho_Chi_Minh` is the front end's job. MariaDB `TIMESTAMP` is never used.
- **Enums:** `VARCHAR(20)` + `CHECK (col IN (…))` + PHP backed enums in `app/Enums`, cast on the model. Never MariaDB's `ENUM` type.
- **Generated key columns carry binary collations** (`utf8mb4_bin`, `ascii_bin`, or `BINARY(32)`), so 'Tổ 1' and 'To 1' stay distinct values.
- **JSON columns:** Laravel's `json()` type (on MariaDB: `LONGTEXT` + `json_valid()` CHECK), `AsArrayObject`/`array` casts.
- **URIs are English** (`/shelves/{shelf}/books/{book}`), route names mirror the URI, Ziggy exposes them to React. UI copy is Vietnamese only, never inline in TSX: client copy in `resources/js/lib/copy.ts`, server copy in `lang/vi/`, enforced by Biome's `noJsxLiterals`.
- **No hand-written `where('bookshelf_id', …)`** outside `app/Models/Scopes/BookshelfScope.php` — the Architecture suite greps for it.
- **Tests:** Pest with `RefreshDatabase` against the **separate** `olibra_testing` schema on the same MariaDB server. Every `<env>` in `phpunit.xml` carries `force="true"` (the priest-liturgy `known-gaps.md` trap), and `EnvironmentTest` proves the guard.
- **Toolchain:** Bun for all JS locally (`bun install`, `bun run …`) — this repo's standing rule; the committed lockfile stays `bun.lock`. Composer for PHP. Larastan level 8 and Pint must stay clean at every commit.
- **The injectable DB clock is gone** (spec §4's `olibra_now()` row): tests move time with `Carbon::setTestNow()`. The application-side `Clock` binding the spec mentions arrives with the first Action class in Phase 1 — nothing in Phase 0 reads domain time.
- **Scratch output** goes to `.artifacts/` (gitignored), never the repo root or `/tmp`.
- **Commit at the end of every task**, lowercase `type: sentence` style.

Create `docker-compose.laravel.yml`. Ports are off the defaults because the Next.js stack (`compose.yaml`) and its Postgres already hold 3001/5435/5436 — both stacks must run side by side for the whole migration, one being what you changed and the other what you compare against:

```yaml
services:
  app:
    build: ./docker/php
    restart: unless-stopped
    volumes: [".:/app"]
    ports: ["${LARAVEL_APP_PORT:-8100}:80"]
    # Deliberately NO env_file. Laravel reads .env from the mounted volume;
    # injecting the same values as real container environment variables makes
    # them impossible for phpunit.xml to override, and that exact interaction
    # silently ran priest-liturgy's suite against its development database.
    depends_on:
      mariadb:
        condition: service_healthy

  scheduler:
    build: ./docker/php
    restart: unless-stopped
    volumes: [".:/app"]
    # schedule:work re-invokes schedule:run every minute — the same shape as
    # production's cron line, so a job that only works under a daemon fails
    # here too. Queue draining rides this tick (Task 21, routes/console.php).
    command: php artisan schedule:work
    depends_on: [app]

  vite:
    image: oven/bun:1.2
    working_dir: /app
    volumes: [".:/app"]
    command: sh -c "bun install && bun run laravel:dev -- --host 0.0.0.0"
    ports: ["${LARAVEL_VITE_PORT:-5175}:5175"]

  mariadb:
    image: mariadb:10.11
    restart: unless-stopped
    environment:
      MARIADB_DATABASE: olibra
      MARIADB_USER: olibra
      MARIADB_PASSWORD: secret
      MARIADB_ROOT_PASSWORD: secret
    volumes:
      - mariadbdata:/var/lib/mysql
      - ./docker/mariadb/init:/docker-entrypoint-initdb.d:ro
    ports: ["${LARAVEL_DB_PORT:-3310}:3306"]
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 5s
      timeout: 5s
      retries: 20
      start_period: 30s

volumes:
  mariadbdata:
```

**Files:**

- Test: `tests/Unit/FoldTest.php`

**Interfaces:**

- Produces: `App\Support\Fold::fold(string $value): string`, the single normalisation BR §12 requires. Task 4's `FoldExpression` parity test compares the database against **this** function; Task 19's factories and every later phase's search/slug code call it. The reference implementation it must match byte-for-byte is `src/domain/kernel/fold.ts`'s `fold()`.

The TypeScript original (still in the working tree, the reference implementation until cutover):

```ts
value.normalize("NFD")
    .replace(/[̀-ͯ]/g, "")   // combining marks
    .replace(/đ/g, "d")
    .replace(/Đ/g, "D")
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, " ")
    .trim()
```

Two properties are load-bearing and must survive translation. **đ→d is explicit**: đ (U+0111) is a distinct Vietnamese letter, not a d with a mark — NFD does not decompose it and the mark-strip leaves it alone; without the explicit rule, searching *dat rung* never finds *Đất Rừng Phương Nam*. **The mark-strip range is `̀–ͯ`** (the Combining Diacritical Marks block), exactly as the TS has it — not `\p{Mn}` — because BR §12 requires the stored normalisation and the search normalisation to be *identical*, and the PHP twin of a TS function is only its twin if it makes the same choices, including this one. (priest-liturgy's `Normalise::fold` uses `\p{Mn}` and also folds ð; OLibra's rule deliberately does neither, because its other half already exists and is shipped.)

```php
<?php

namespace App\Support;

/**
 * Diacritic- and case-insensitive folding of Vietnamese text.
 *
 * The byte-for-byte twin of `fold()` in src/domain/kernel/fold.ts — BR §12
 * requires that whatever normalisation is applied when storing a title is the
 * IDENTICAL normalisation applied to the search term, so the two can never
 * drift. Three parties must agree: this function, the generated-column SQL
 * emitted by FoldExpression (Task 4), and — until cutover — the TypeScript
 * original. tests/Unit/FoldTest.php and tests/Feature/FoldParityTest.php are
 * the agreement's enforcement, not documentation of it.
 *
 * đ needs its own rule and must not be removed: it is a distinct Vietnamese
 * letter, not a d carrying a diacritic, so NFD does not decompose it and the
 * combining-mark strip leaves it untouched.
 *
 * The mark-strip range is \x{0300}-\x{036f}, mirroring the TS regex exactly —
 * deliberately narrower than \p{Mn}. Same choices, or not a twin.
 */
final class Fold
{
    public static function fold(string $value): string
    {
        $decomposed = (string) \Normalizer::normalize($value, \Normalizer::FORM_D);
        $stripped = (string) preg_replace('/[\x{0300}-\x{036f}]/u', '', $decomposed);
        $deStroked = strtr($stripped, ['đ' => 'd', 'Đ' => 'D']);
        $lowered = mb_strtolower($deStroked, 'UTF-8');
        $spaced = (string) preg_replace('/[^a-z0-9]+/u', ' ', $lowered);

        return trim($spaced);
    }

    /** True when $needle, folded, appears anywhere in $haystack, folded. */
    public static function matches(string $haystack, string $needle): bool
    {
        return str_contains(self::fold($haystack), self::fold($needle));
    }
}
```

(`Normalizer` comes from `ext-intl`, which the Dockerfile installs and the host survey's row 4 confirms.)

MariaDB has no `unaccent` and forbids stored functions in generated columns, so the Postgres `olibra_fold()` becomes a generated nested-`REPLACE()` chain — spec §4.2 option 1. The chain is emitted by this class rather than pasted, so the 67-entry map is maintained as data. `LOWER()` runs first (utf8mb4's Unicode case mapping handles the uppercase precomposed letters), then the map replaces each lowercase accented letter, then `REGEXP_REPLACE` collapses everything non-alphanumeric — which also disposes of any code point outside the map (CJK, ð, emoji) exactly as the PHP regex does.

That decision is taken by editing Task 7's Step 3 to plain columns plus an observer in `Book::booted()` — and recording the switch in `docs/HOSTING.md` row 10 — not by improvising mid-migration. The condition that triggers it is a failing migration or a failing `FoldParityTest` on MariaDB 10.11, nothing vaguer.

Create `app/Support/FoldExpression.php`:

```php
<?php

namespace App\Support;

/**
 * Emits the MariaDB generated-column expression that reproduces Fold::fold().
 *
 * Spec §4.2 option 1: MariaDB has no unaccent() and forbids stored functions
 * inside generated-column expressions, so folding becomes a nested REPLACE()
 * chain over the Vietnamese code points — roughly 2 KB of SQL, ugly but
 * emitted rather than maintained. tests/Feature/FoldParityTest.php asserts
 * DB folding === PHP folding over the corpus; that test, not this class's
 * readability, is what keeps the two honest.
 *
 * LOWER() runs first: utf8mb4's Unicode case mapping folds every uppercase
 * precomposed letter to its lowercase twin (Ệ→ệ, Đ→đ), which is why the map
 * needs only lowercase keys — đ→d then covers Đ too. The all-caps case in
 * FoldParityTest's corpus is what proves LOWER() actually did this on the
 * running server. REGEXP_REPLACE then turns every remaining non-[a-z0-9]
 * run — punctuation, spaces, and any code point the map does not know —
 * into one space, exactly what the PHP /[^a-z0-9]+/u does.
 */
final class FoldExpression
{
    /** @var array<string, string> lowercase Vietnamese code point → ascii */
    public const MAP = [
        'à' => 'a', 'á' => 'a', 'ả' => 'a', 'ã' => 'a', 'ạ' => 'a',
        'ă' => 'a', 'ằ' => 'a', 'ắ' => 'a', 'ẳ' => 'a', 'ẵ' => 'a', 'ặ' => 'a',
        'â' => 'a', 'ầ' => 'a', 'ấ' => 'a', 'ẩ' => 'a', 'ẫ' => 'a', 'ậ' => 'a',
        'è' => 'e', 'é' => 'e', 'ẻ' => 'e', 'ẽ' => 'e', 'ẹ' => 'e',
        'ê' => 'e', 'ề' => 'e', 'ế' => 'e', 'ể' => 'e', 'ễ' => 'e', 'ệ' => 'e',
        'ì' => 'i', 'í' => 'i', 'ỉ' => 'i', 'ĩ' => 'i', 'ị' => 'i',
        'ò' => 'o', 'ó' => 'o', 'ỏ' => 'o', 'õ' => 'o', 'ọ' => 'o',
        'ô' => 'o', 'ồ' => 'o', 'ố' => 'o', 'ổ' => 'o', 'ỗ' => 'o', 'ộ' => 'o',
        'ơ' => 'o', 'ờ' => 'o', 'ớ' => 'o', 'ở' => 'o', 'ỡ' => 'o', 'ợ' => 'o',
        'ù' => 'u', 'ú' => 'u', 'ủ' => 'u', 'ũ' => 'u', 'ụ' => 'u',
        'ư' => 'u', 'ừ' => 'u', 'ứ' => 'u', 'ử' => 'u', 'ữ' => 'u', 'ự' => 'u',
        'ỳ' => 'y', 'ý' => 'y', 'ỷ' => 'y', 'ỹ' => 'y', 'ỵ' => 'y',
        'đ' => 'd',
    ];

    /**
     * @param  string  $expression  a SQL expression: a backtick-quoted column,
     *                              a COALESCE(...), or a bare ? placeholder.
     */
    public static function sql(string $expression): string
    {
        $inner = "LOWER({$expression})";

        foreach (self::MAP as $from => $to) {
            $inner = "REPLACE({$inner}, '{$from}', '{$to}')";
        }

        return "TRIM(REGEXP_REPLACE({$inner}, '[^a-z0-9]+', ' '))";
    }
}
```

Schema conventions used in every migration of Tasks 6–10, stated once here and applied without further comment:

- UUID keys and refs: `$table->char('id', 36)->charset('ascii')->collation('ascii_bin')` — matching types and collations everywhere or MariaDB refuses the Task 11 FKs.
- Timestamps: `$table->dateTime('created_at', 6)->useCurrent();` etc. — `DATETIME(6)`, UTC by application convention; Eloquent overwrites the DB default on model writes, the default exists for raw inserts.
- Enum columns: `$table->string('col', 20)->default('…')` + a raw `CHECK (col IN (…))` — the label list copied verbatim from Task 5.
- CHECK constraints and generated columns are added by `DB::statement()` after `Schema::create()` — Laravel's Blueprint has no CHECK builder, and writing the generated columns as raw SQL keeps the exact DDL reviewable.
- `down()` is `Schema::dropIfExists(...)` — forward-only in production, reversible in dev.

```php
                    IF(deleted_at IS NULL,
                       UNHEX(SHA2(CONCAT_WS(0x1f, bookshelf_id, level, IFNULL(parent_id, ''), name), 256)),
                       NULL)
                ) STORED
        ");
        DB::statement('ALTER TABLE parish_units ADD CONSTRAINT parish_units_name_unique_in_scope UNIQUE (name_scope_key)');
```

**The single-row-PK decision** (the brief's open point, decided here): Postgres used `id boolean primary key default true check (id)`. MariaDB has no boolean-pk idiom — `BOOLEAN` is `TINYINT(1)` — so the port is `id TINYINT UNSIGNED PRIMARY KEY DEFAULT 1` with `CHECK (id = 1)`: a second row is a clean 1062 duplicate-key error exactly as before, the migration inserts the one row so every read is a plain `SELECT`, and the CHECK stops an id of 0 or 2 sneaking in through a raw write.                 SIGNAL SQLSTATE '45000'

```php
        // 20260808_02: the slug is the shelf's public identity — QR labels
        // and printed URLs point at it; renaming a shelf must not orphan them.
        DB::unprepared("
            CREATE TRIGGER bookshelves_slug_immutable BEFORE UPDATE ON bookshelves FOR EACH ROW
                IF NEW.slug <> OLD.slug THEN
                    SIGNAL SQLSTATE '45000'
                    SET MESSAGE_TEXT = 'bookshelves.slug is immutable after creation';
                END IF
        ");

        // 20260810_10: feedback belongs where it was filed, forever — moving
        // it between shelves (or claiming front-door feedback for a shelf)
        // would rewrite who is allowed to read it. <=> is the NULL-safe
        // comparison; bookshelf_id is nullable here.
        DB::unprepared("
            CREATE TRIGGER feedback_bookshelf_immutable BEFORE UPDATE ON feedback FOR EACH ROW
                IF NOT (NEW.bookshelf_id <=> OLD.bookshelf_id) THEN
                    SIGNAL SQLSTATE '45000'
                    SET MESSAGE_TEXT = 'feedback.bookshelf_id is immutable after creation';
                END IF
        ");
    }

        DB::unprepared('DROP TRIGGER IF EXISTS loans_no_delete');
        DB::unprepared('DROP TRIGGER IF EXISTS audit_log_no_update');
        DB::unprepared('DROP TRIGGER IF EXISTS audit_log_no_delete');
        DB::unprepared('DROP TRIGGER IF EXISTS bookshelves_slug_immutable');
```

Create `app/Support/TenantContext.php`:

```php
<?php

namespace App\Support;

use App\Models\Bookshelf;
use App\Models\Membership;

/**
 * Everything a request knows about where it is and who is asking — the
 * Laravel form of src/domain/kernel/tenant.ts's TenantContext. Registered as
 * a scoped singleton (fresh per request), populated exactly once, by the
 * ResolveTenant middleware (Task 16). Nothing else may call set().
 *
 * Null bookshelf means "no shelf bound" — the portal, auth screens, admin
 * screens, console commands. BookshelfScope then adds nothing, and system
 * jobs name their own bookshelf_id explicitly, mirroring priest-liturgy's
 * OwnedByCurrentUser no-op.
 */
final class TenantContext
{
    private ?Bookshelf $bookshelf = null;

    private ?Membership $membership = null;

    public function set(Bookshelf $bookshelf, ?Membership $membership): void
    {
        $this->bookshelf = $bookshelf;
        $this->membership = $membership;
    }

    public function bookshelf(): ?Bookshelf
    {
        return $this->bookshelf;
    }

    public function bookshelfId(): ?string
    {
        return $this->bookshelf?->id;
    }

    public function membership(): ?Membership
    {
        return $this->membership;
    }

    public function clear(): void
    {
        $this->bookshelf = null;
        $this->membership = null;
    }
}
```

```php
<?php

namespace App\Models\Scopes;

use App\Support\TenantContext;
use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Scope;

/**
 * The ONLY place in the codebase allowed to filter on bookshelf_id — the
 * Architecture suite (Task 15) greps everything else. When no shelf is
 * bound the scope adds nothing: console commands and scheduled jobs reach
 * data by naming their own bookshelf_id, never by impersonating a tenant.
 *
 * @implements Scope
 */
class BookshelfScope implements Scope
{
    /**
     * @param  Builder<covariant Model>  $builder
     */
    public function apply(Builder $builder, Model $model): void
    {
        $bookshelfId = app(TenantContext::class)->bookshelfId();

        if ($bookshelfId === null) {
            return;
        }

        $builder->where($model->getTable().'.bookshelf_id', $bookshelfId);
    }
}
```

```php
<?php

namespace App\Models\Concerns;

use App\Models\Bookshelf;
use App\Models\Scopes\BookshelfScope;
use App\Support\TenantContext;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;

/**
 * Every shelf-scoped model carries this — spec §5.2's routine layer. The
 * global scope reads the bound shelf; the creating hook stamps bookshelf_id
 * so no controller or action ever writes it by hand. The structural layer
 * (composite FKs, Task 11) survives a bug in this one.
 */
trait BelongsToBookshelf
{
    public static function bootBelongsToBookshelf(): void
    {
        static::addGlobalScope(new BookshelfScope);

        static::creating(function (Model $model): void {
            if ($model->getAttribute('bookshelf_id') === null) {
                $model->setAttribute('bookshelf_id', app(TenantContext::class)->bookshelfId());
            }
        });
    }

    public function bookshelf(): BelongsTo
    {
        return $this->belongsTo(Bookshelf::class);
    }
}
```

```php
<?php

use App\Models\Concerns\BelongsToBookshelf;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\File;

/**
 * Models allowed to carry a bookshelf_id column WITHOUT the trait, each for
 * a recorded reason: nullable shelf link, scoped-by-hand in app/Queries.
 */
const TENANCY_EXEMPT = ['App\Models\Feedback', 'App\Models\AuditLog'];

/** @return array<class-string<\Illuminate\Database\Eloquent\Model>> */
function allModelClasses(): array
{
    return collect(File::files(app_path('Models')))
        ->map(fn ($file) => 'App\\Models\\'.$file->getFilenameWithoutExtension())
        ->filter(fn (string $class) => class_exists($class)
            && is_subclass_of($class, Illuminate\Database\Eloquent\Model::class))
        ->values()
        ->all();
}

it('puts BelongsToBookshelf on every model whose table carries bookshelf_id', function () {
    foreach (allModelClasses() as $class) {
        $table = (new $class)->getTable();
        $hasColumn = DB::selectOne('
            select count(*) as n from information_schema.columns
            where table_schema = database() and table_name = ? and column_name = ?
        ', [$table, 'bookshelf_id'])->n > 0;

        $hasTrait = in_array(BelongsToBookshelf::class, class_uses_recursive($class), true);

        if (! $hasColumn) {
            expect($hasTrait)->toBeFalse("{$class} has the trait but no bookshelf_id column");

            continue;
        }

        if (in_array($class, TENANCY_EXEMPT, true)) {
            // The exemption is only legitimate while the column is nullable —
            // a later migration making it NOT NULL must break this test.
            $nullable = DB::selectOne('
                select is_nullable from information_schema.columns
                where table_schema = database() and table_name = ? and column_name = ?
            ', [$table, 'bookshelf_id'])->is_nullable;

            expect($nullable)->toBe('YES', "{$class} is exempt but its bookshelf_id is NOT NULL")
                ->and($hasTrait)->toBeFalse("{$class} is exempt and must not carry the trait");

            continue;
        }

        // The teeth: a model added in any later phase without the trait
        // fails the build here rather than quietly serving every shelf.
        expect($hasTrait)->toBeTrue("{$class} is shelf-scoped but does not use BelongsToBookshelf");
    }
});

it('confines bookshelf_id filtering to BookshelfScope', function () {
    $offenders = [];

    foreach (File::allFiles(app_path()) as $file) {
        if (str_ends_with($file->getPathname(), 'app/Models/Scopes/BookshelfScope.php')) {
            continue;
        }

        if (preg_match('/where\s*\(\s*[\'"][^\'"]*bookshelf_id/', $file->getContents())) {
            $offenders[] = $file->getRelativePathname();
        }
    }

    // Spec §10 risk 1: read-side protection now lives in the model layer,
    // and a hand-written filter is the tell of code bypassing it.
    expect($offenders)->toBe([]);
});
```

- Consumes: `User` (Task 14 — `getAuthPasswordName()` already points the guard at `password_hash`), `TenantContext`, `Membership`, `Bookshelf`.
- Produces: `POST /login` (name `login`), `POST /logout` (name `logout`); the `tenant` middleware alias every `/shelves/{shelf}/…` route group carries from Task 18 on; `TenantContext` populated with the bound shelf and the signed-in user's **active** membership of it.

**The sessions decision** (the brief's open point, decided here): the design's custom `sessions` table stored `sha256(token)` so a leaked backup is not a stack of usable sessions. This plan **adopts Laravel's own database session driver instead** — the table Task 6 already created. What is gained: CSRF, session regeneration on login, guard integration, `Auth::logoutOtherDevices`, and zero bespoke crypto to maintain. What is conceded: Laravel stores the session id verbatim in the table, so the hashed-at-rest property is lost. Why the concession is acceptable here: the threat was a leaked *backup*, and under shared hosting the session rows live in the same MariaDB, same single user, same `mysqldump` as everything else — a backup leak already yields the password hashes and all data, sessions expire (`SESSION_LIFETIME=43200`, 30 days, matching today's `SESSION_DAYS = 30`), and ids rotate on every login. The property the old design must **not** lose is revocation — deleting or soft-deleting a user must kill their live sessions in substance — and that survives: the `users` provider excludes soft-deleted rows, so a trashed user's session stops resolving on the next request (asserted below), and the FK added in Task 6 hard-deletes rows with the user. Building a custom `token_hash` guard would spend the phase's riskiest budget re-implementing what the framework does well, against the spec's own "Laravel-idiomatic" decision (§1.3).

```php
<?php

namespace App\Http\Requests\Auth;

use App\Models\User;
use Illuminate\Auth\Events\Lockout;
use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Str;
use Illuminate\Validation\ValidationException;

class LoginRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    /** @return array<string, array<int, string>> */
    public function rules(): array
    {
        return [
            'username' => ['required', 'string'],
            'password' => ['required', 'string'],
        ];
    }

    /**
     * Username + password against users.password_hash. Not Auth::attempt():
     * the lookup must be LOWER() = LOWER() on a binary column — the same
     * semantics src/auth/session.ts::signIn ships — and a missing account
     * must burn a hash verification anyway so an unknown username and a
     * wrong password take the same time to fail.
     *
     * @throws ValidationException
     */
    public function authenticate(): void
    {
        $this->ensureIsNotRateLimited();

        /** @var User|null $user */
        $user = User::query()
            ->whereRaw('LOWER(username) = ?', [Str::lower($this->string('username')->toString())])
            ->first();

        // A dummy argon2id hash of a random string nobody knows; verifying
        // against it equalises timing for unknown users and credential-less
        // accounts (INV-14 rows have password_hash null).
        $stored = $user?->password_hash
            ?? '$argon2id$v=19$m=65536,t=4,p=1$c29tZXNhbHRzb21lc2FsdA$Yk1nZFhLeHhPTUJoTUlNTXlwSllvWkRSbjJKcVZGdkc';

        $ok = Hash::check($this->string('password')->toString(), $stored)
            && $user !== null
            && $user->password_hash !== null;

        if (! $ok) {
            RateLimiter::hit($this->throttleKey());

            // One message for every failure mode — never confirm which
            // usernames exist. The string lives in lang/vi/auth.php.
            throw ValidationException::withMessages(['username' => __('auth.failed')]);
        }

        RateLimiter::clear($this->throttleKey());
        Auth::login($user);
    }

    /** @throws ValidationException */
    public function ensureIsNotRateLimited(): void
    {
        if (! RateLimiter::tooManyAttempts($this->throttleKey(), 5)) {
            return;
        }

        event(new Lockout($this));

        throw ValidationException::withMessages([
            'username' => __('auth.throttle', ['seconds' => RateLimiter::availableIn($this->throttleKey())]),
        ]);
    }

    public function throttleKey(): string
    {
        return Str::transliterate(Str::lower($this->string('username')->toString()).'|'.$this->ip());
    }
}
```

```php
public function boot(): void
{
    // The global flag outranks every shelf role — ROLE_RANK.super_admin.
    // Returning null (not false) lets the per-gate checks run for everyone else.
    Gate::before(fn (User $user) => $user->is_super_admin ? true : null);
```

```php
class HandleInertiaRequests extends Middleware
```

- [ ] **Step 1: Schedule the queue drain**

Append to `routes/console.php`:

```php
use Illuminate\Support\Facades\Schedule;

// No daemon on shared hosting. The per-minute schedule:run tick (cron, below)
// drains the queue instead: stop when empty, never outlive the next tick's
// slot. Worst-case latency for a queued job is about a minute, which BR §15's
// notification model tolerates (spec §10 risk 4).
Schedule::command('queue:work --stop-when-empty --max-time=50')
    ->everyMinute()
    ->withoutOverlapping();
```

(The 07:00 Asia/Ho_Chi_Minh reminder sweep is Phase 2's — it slots in here as a second `Schedule::` line when the sweep command exists. Scheduling a command that does not exist yet would fail every tick.)

- [ ] **Step 2: Write the deploy workflow**

Create `.github/workflows/deploy-laravel.yml`. Manual dispatch — deploys are a decision, not a side effect of merging:

```yaml
name: Deploy (cPanel)

on:
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    environment: production
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: "8.4"
          extensions: pdo_mysql, intl, zip, bcmath, gd, mbstring
          coverage: none

      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: "1.2"

      # Build off-host: no Node and no Composer are needed on the host at
      # deploy time (spec §8). vendor/ ships in the artifact.
      - name: Build
        run: |
          composer install --no-dev --optimize-autoloader --no-interaction --prefer-dist
          bun install --frozen-lockfile
          bun run laravel:build

      - name: Assemble artifact
        run: |
          mkdir -p .artifacts
          rsync -a \
            --exclude='.git' --exclude='.github' --exclude='.artifacts' \
            --exclude='node_modules' --exclude='src' --exclude='tests' \
            --exclude='docker' --exclude='docker-compose.laravel.yml' \
            --exclude='compose.yaml' --exclude='next.config.ts' \
            --exclude='storage/logs' --exclude='.env' \
            ./ .artifacts/release/

      - name: Ship (rsync over ssh)
        env:
          DEPLOY_KEY: ${{ secrets.DEPLOY_SSH_KEY }}
          DEPLOY_HOST: ${{ secrets.DEPLOY_HOST }}
          DEPLOY_USER: ${{ secrets.DEPLOY_USER }}
          DEPLOY_PATH: ${{ secrets.DEPLOY_PATH }}
        run: |
          mkdir -p ~/.ssh
          echo "$DEPLOY_KEY" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          ssh-keyscan -H "$DEPLOY_HOST" >> ~/.ssh/known_hosts
          rsync -az --delete \
            --exclude='.env' --exclude='storage/app' --exclude='storage/framework' \
            .artifacts/release/ "$DEPLOY_USER@$DEPLOY_HOST:$DEPLOY_PATH/"
          ssh "$DEPLOY_USER@$DEPLOY_HOST" "bash $DEPLOY_PATH/deploy/post-deploy.sh $DEPLOY_PATH"
```

Secrets to create in the repository settings before the first run: `DEPLOY_SSH_KEY`, `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH` (e.g. `/home/<account>/olibra`). If `docs/HOSTING.md` row 12/14 chose cPanel Git instead of rsync, the Ship step is replaced by a push to the cPanel remote and `.cpanel.yml` (below) does the copy — both channels are written; the survey row picks which one is wired.
